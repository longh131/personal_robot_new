# 受控底盘测试方案（设计，未执行）

适用：未来 2B-2（只读）、2C（单帧写）、2D（停车）。每一档须单独批准。  
冻结安全接口见 `docs/safety_interface.md`。协议证据见 `docs/c30d_protocol_evidence.md`。

## 前置条件（所有涉及串口/运动的步骤）

- 麦克纳姆轮离地或整车顶起，轮可转但不触地。
- `/dev/c30d` 存在、权限 `dialout`、无占用。
- 操作者可立即拔 USB 或切底盘电源。
- **无独立硬件急停（事实）。零速与反向制动均未验证，不得视为急停。**
- 禁止归档 `c30d_node`、`single_test.py`、无限循环写。
- 默认 dry-run：先打印将发字节，不 open；获批后再改。

## 最低风险顺序

| 步 | 内容 | 时长上限 | 停止条件 |
|---|---|---|---|
| 0 | dry-run 组帧打印 | — | — |
| 1 | 只读 open，记录 RX（2B-2） | 5 s | 超时 close；异常 close |
| 2 | 写 1 帧全零，观察是否动（2C） | 写完即停发，观察 ≤2 s | 任何非预期运动 → 拔 USB |
| 3 | 写 1 帧假说极小 vx（如 60），≤0.2 s 窗口（2C） | 单帧 | 超时 close；H1 失败则停止扩大 |
| 4 | 仅当 3 能重复产生运动后：停车对比 S0 停发 / S1 零帧 / S2 反向（默认不做）/ S3 杀进程 / S4 拔 USB（2D） | 每项运动脉冲尽量短，观察 ≤2 s | 时间盒到记失败并 close |

禁止：随机扫字节、连续流式速度、H1 失败后换协议盲探（除非另批）。

## 动作时长

- 只读：一次会话 ≤5 s。
- 运动写：每个批准用例 **一帧或一个时间盒**，默认运动意图 ≤0.2 s。
- 观察窗 ≤2 s。不得 while True。

## 异常处置

| 现象 | 动作 |
|---|---|
| 打不开 / 权限 / 被占 | 停，不重试写 |
| 轮触地或无法确认离地 | 停 |
| 非预期方向、持续转、加速 | close + 拔 USB/断电，记失败 |
| 进程卡住 | SIGKILL（避免 SIGINT 走未验证零速钩子），必要时拔 USB |

## 停止后状态确认（须记录，不得靠“已发零速”）

1. 脚本已 close，无进程占串口（proc fd 扫描）。
2. 目视：四轮是否仍转。
3. 若仍转：断电/拔 USB，记「软件无法停」。
4. 写明本次实际使用的停止手段（停发 / 零帧 / 拔线），以及是否成功。
