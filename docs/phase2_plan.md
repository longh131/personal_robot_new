## 0. 已验证事实 vs 待验证假设

### 已验证事实

- 串口设备：`/dev/c30d` → `ttyACM0`；USB `1a86:55d4`，序列 `5C98181506`。
- 用户在 `dialout`；波特率历史上为 115200（设备存在，波特率本身未在本阶段用示波器/抓包复核）。
- 遗留实验包已归档；`single_test.py` 会无限发 `vx=60`，禁止运行。
- 遗留组帧代码：`0x7B, 0x00, 0x00, vx_be, vy_be, wz_be, xor, 0x7D`（int16 大端）。**只证明“旧代码这么写”，不证明固件如此解析。**
- 厂商 zip 中 USART2 把 `0x7B`/`0x7D` 当 APP PID ASCII 帧；ROS `Check_Sum` 已注释。**只证明这份源码如此，不证明板上固件与 zip 一致。**
- 历史口头结论：前进/后退/左移/右移曾成功。**无本次可引用抓包。**
- 无已验证独立硬件急停（KI-003）。
- 软件急停上限：仅当串口可写且固件承认停止帧。

### 待验证假设（不得当事实）

- H1：USB CDC 上实际运动协议就是遗留二进制 11 字节帧。
- H2：校验为帧头至校验前所有字节 XOR，等于末字节前一字节。
- H3：vx/vy/wz 单位为 mm/s 与 mrad/s 或类似整数；遗留 `Twist * 300` 映射正确。
- H4：全零速度帧使电机停止且不反转。
- H5：反向速度可作制动且不产生可观察反向位移。
- H6：停止写串口、进程退出、拔 USB 后，电机会停而不是保持最后速度。
- H7：错误帧会被丢弃，而不会被当成 APP 方向键/PID。
- H8：轮序 A/B/C/D 与 Mec-V 运动学与速度符号一致。

## 2. 安全控制层设计（Phase 2 冻结接口，Phase 4 实现节点）

Phase 2 不实现 `safety_manager` 节点，但协议测试必须服从下列契约，避免后续把“随便写串口”固化进驱动。

### 2.1 原则

- 急停是独立锁存，不是 `IDLE/AWAKE/REMOTE/FAULT` 之一。
- 仅一条速度出口到底盘驱动：建议名 `/cmd_vel_safe`（`geometry_msgs/Twist`）。
- AI/远程/teleop 不得打开 `/dev/c30d`。
- 无许可或急停锁存时，驱动不得发送非零运动帧。
- **“停止帧”内容以本节第 3 章验证结果填入，不得预先写成全零。** 在 H4 被证实或证伪之前，测试计划把“候选停止帧”与“急停能力”分开记录。

### 2.2 模式与许可

| 模式 | 运动许可 | 允许的命令源 |
|---|---|---|
| IDLE | 无 | 无 |
| AWAKE | 有（独占） | `awake` |
| REMOTE | 有（独占） | `remote` |
| FAULT | 无 | 无 |

AWAKE ↔ REMOTE 禁止直切：必须 `revoke` → 确认不再发非零帧 → 可选等待“安全静止”（定义见第 3 章）或进 FAULT → `grant`。

### 2.3 急停三类（能力上限写进验收）

| 类型 | 行为 | 已验证能力 |
|---|---|---|
| 软件急停 | 锁存；切断许可；按已验证停车策略发帧（若有） | **待 Phase 2** |
| 通信失联 | 命令超时（建议 200–500 ms，待测）走软件急停路径 | **待测** |
| 硬件急停 | 独立切断动力 | **不具备（事实）** |

清除急停必须人工。禁止超时自动解锁。

### 2.4 建议 ROS 接口（实现阶段再编码）

- `/robot/mode`（自定义或 `std_msgs/String`，Phase 4 可再定消息包）
- `/robot/estop`（`std_msgs/Bool`，true=锁存）
- `/robot/fault`（字符串/诊断）
- 输入：`/cmd_vel_remote`、`/cmd_vel_awake`（仅 Safety 订）
- 输出：`/cmd_vel_safe` → 仅未来 `c30d_driver` 订

Phase 2 的 `hardware_test` 脚本**不是**上述节点；脚本须独立、默认可 dry-run，且默认 `dry_run=true`。

## 3. 协议核实计划

### 3.1 静态（无串口，默认可执行）

- 对照遗留 `build_frame` 与厂商 `usartx.c`，列出差异表（二进制速度帧 vs APP ASCII vs 已注释 Check_Sum）。
- 用纯函数单测：给定 vx,vy,wz → 期望字节（**测的是旧假说组帧，不是固件**）。
- 禁止 import 归档包作为正式库；允许只读复制常量到 `hardware_test/c30d/protocol/` 并标注 `HYPOTHESIS`。

验收：差异表写入 `docs/`；单测不打开任何 `/dev/tty*`。

### 3.2 只读监听（打开串口但不写入）

- 设备：仅 `/dev/c30d` 或 by-id；115200 8N1 为假设，先试，失败则停。
- 时长：固定（如 5 s），只记录 RX。
- 停止条件：超时结束；异常立即 close。

验收：有无主动上报（编码器/心跳）记为事实。无写入。

### 3.3 受控写入（必须另批，轮子离地）

每条用例：预置离地、单次或短脉冲、**硬停止条件**（时间盒 + 键盘/Ctrl+C 立即 close 且不再写）。禁止循环。禁止调用归档 `single_test.py`。

建议顺序（每条单独批准）：

1. 发送一帧全零，观察电机是否动（预期：不动）。
2. 发送一帧与遗留格式一致的极小 vx，时长 ≤0.2 s，然后 close。记录是否动、方向。
3. 若 H1 失败：停止扩大，改文档，不猜测第二种协议除非用户批准下一探测。

禁止在 H1 未成立时批量扫描随机字节（误触发 APP 方向键风险，H7）。

## 4. 停车策略验证（必须另批，轮子离地）

在 H1 成立且能重复产生运动之后才做。否则停车结论无效。

候选（均为假设，先离地）：

| ID | 策略 | 关注点 |
|---|---|---|
| S0 | 停发（不再写） | 是否滑行/保持末速度 |
| S1 | 周期性全零帧 | 是否停、是否抖、是否反向 |
| S2 | 短时反向小速度再停发 | 是否倒车（KI-002） |
| S3 | 进程 SIGINT / SIGKILL | 退出钩子是否写串口；KILL 后底盘行为 |
| S4 | 关闭串口 / 拔 USB | 无软件急停时的真实上限 |

每项：运动脉冲尽可能短 → 立即施加策略 → 记录停止时间或“未停/反向”。时间盒（如 2 s）到则记失败并停发+close。

**验收规则：**

- 仅当某策略在离地条件下可重复使轮速到可观察静止，才允许写入“软件停止手段”。
- 若 S1 不能停：明确 **零速 ≠ 急停**（强化 KI-001），Phase 3 驱动不得把 watchdog 零速宣传为急停。
- 若 S2 造成反向：禁止作为默认制动。
- 若仅有 S0/S4 有效或全部无效：文档写明软件急停能力不足，Phase 3 限速+人工断电流程。

## 5. 分阶段测试与验收

| 子阶段 | 可否自动开始 | 通过标准 | 失败 |
|---|---|---|---|
| 2A 静态组帧/对照 | 审核通过本文后 | 单测绿；差异表完成 | 停，不写串口 |
| 2B 只读串口 | 2A 通过后另口头/书面确认即可 | 能打开 `/dev/c30d`，只读日志，进程退出 close | 关串口 |
| 2C 单帧写入 | **单独批准**，确认离地 | 记录固件对假说帧的反应；有硬超时 | 停发 close；不进入 2D |
| 2D 停车对比 | **单独批准** | 各策略有结果表；选定或否决默认停止策略 | 同上 |
| 2E 文档 | 2A–2D 做到哪写到哪 | `docs/` 更新协议、停车、KI；事实/假设已改标签 | — |

Phase 2 完成定义：2A 必做；2B 建议做；2C/2D 仅在用户批准后；即使 2C 失败，只要文档把 H1 标为伪，且不把零速当急停，也可申请关闭 Phase 2（范围降级须你确认）。

## 6. 失败与扩大禁令

- 与环境不符（无 `/dev/c30d`、权限失败、轮未离地）：立即停。
- 不装软件、不改 udev/固件、不 git、不跑旧节点。
- 不把 `hardware_test` 挂进默认 bringup。
- 正式驱动留给 Phase 3，且必须订阅未来的 `/cmd_vel_safe`，不得直订 `/cmd_vel`。
