# Personal Robot 框架（讨论稿）

- 日期：2026-10-19
- 状态：**已确认（2026-10-19）。** 顺序：相机 → 音频 → 总线+技能(+LED/蜂鸣) → REMOTE → AWAKE。技能只发 ID，履约在 `ros2_ws`。旧 zip 只读。

## 1. 现在的 `ros2_ws` 能不能撑后面

**已经能撑的：** 底盘走 Safety → `/cmd_vel_safe` → 驱动；`IDLE/AWAKE/REMOTE/FAULT` 互斥；急停锁存；短时着地能走能停。这是后面所有运动的身体。

**还撑不住、不要假装已经有：**

| 能力 | 现状 |
|---|---|
| 跟随 / 避障 | 无雷达节点、无避障、无跟随。Nav2 未装 |
| 跳舞（编号动作段） | 没有技能执行器。只能靠外面按节拍发 Twist |
| 里程计 | 话题在，着地约 15cm 时 `/odom` 仍为 0 |
| 相机 / 麦克风 / 扬声器 | 设备在，未开流、未录音、未播放 |
| Command Bus | 已接 `drive` → `/cmd_vel_remote`。跳舞履约未做 |

结论：电机遥控底座有了。跟随、避障、跳舞、语音、远程界面都还不是 ROS 里的现成能力。

跳舞的正确做法：ROS 里一个 **技能动作**（`skill_id` + 参数），内部按节拍发已限速 Twist，仍只进 Safety。不是 AI/远程各自写一套轮子协议。

---

## 2. 概念

**Personal AI = 整个项目**（人、远程、底盘都算它）。不是「只有语音那一半」。

IDLE 在听两路入口，同时只能进一个：

```
Personal AI
  IDLE 监听
    ├─ 语音唤醒 → AWAKE（拒远程；屏蔽遥控）
    └─ 远程登录 → REMOTE（屏蔽唤醒）
  AWAKE ↔ REMOTE 不能直切，必须回 IDLE
  急停 / FAULT 仍高于模式
```

**要隔开的是 AWAKE 和 REMOTE 这两套产品代码**（目录、进程、插件），不是「项目名 vs 远程」。  
`ros2_ws` 仍是底盘/Safety，两边都用，但不算 AWAKE 插件，也不算 REMOTE 插件。

旧版坑：远程和语音引用同一批 plugin 文件，改一处两边乱。新版：AWAKE 树和 REMOTE 树互不 import。

---

## 3. 「阶段改不改」是什么意思

原来表是：6 远程 → 7 相机 → 8 音频 → 9 语音 → 10 大脑 → 11 导航。

你说过想先测硬件再直接做整机。所以我建议**改顺序**，不是改状态机：

1. 先测相机（能拍照）  
2. 先测喇叭和麦（能听能说，否则 AWAKE 做不了）  
3. 再做「下命令的总线 + 一两个编号动作」  
4. 再做 REMOTE 界面  
5. 再做 AWAKE 语音  
6. 雷达/跟随很后，没硬件写了也是空的  

**不改顺序** = 仍先做远程网页，相机音频往后放。  
你拍板用哪条即可。

---

## 4. 技能：只发 ID（已确认）

是的：**舞蹈等编号动作写在 `ros2_ws` 的 ROS 包里**（身体履约）。AWAKE/REMOTE 只下 `dance_3` 这种 ID，不写轮子节拍，也不互相 import。

---

## 5. 你这边容易漏、现在直接开发会踩的

1. **音频未测**（Yundea 带 USB 声卡，未录音/播放）  
2. **相机未打开**（设备在，哪个 `/dev/video*` 未定）  
3. **`/odom` 着地不准**，跟随/定位不能当已完成  
4. **拔 USB / 杀进程** 未测  
5. **Command Bus 没有**，AI 若直接发 Twist 会和远程抢、也难取消「跳舞」  
6. **4GB 内存**：ROS + 视频 + 本地唤醒 + 云端 LLM 要预算，别默认本地 7B  
7. **无硬件急停**；着地 15cm 停 ≠ 工业急停  
8. **没有雷达** 就没有真跟随/避障  
9. **技能超时与取消**：编号动作必须能被急停/切 IDLE 打断  
10. **认证与公网暴露**：远程未做前不要把端口打到外面  

旧 zip 只当产品流程备忘（问候语、超时回 IDLE、打断 TTS），实现全部新写。
